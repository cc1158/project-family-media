# 家映长期安装版验收清单

统一发布顺序见仓库根目录 `docs/release_process.md`，阻断级真机项目见 `docs/manual_acceptance.md`。本文件保留更细的 Apple 客户端回归场景。

这份清单用于准备长期安装在家庭 Apple TV 和 iPhone 上的版本。每次准备安装新版本时，从上到下执行并记录失败项，不以模拟器结果代替 NAS 真机播放验证。

## 1. 版本与构建

- 在 `project.yml` 中同时更新 iOS 和 tvOS 的 `MARKETING_VERSION` 与 `CURRENT_PROJECT_VERSION`。
- 执行 `python3 scripts/validate_release_configuration.py`，确认版本、Bundle ID、Team、Info.plist 和横竖屏配置一致。
- 执行 `xcodegen generate`，确认生成后的工程只包含预期差异。
- 在设置页确认显示的版本号、构建号与本次安装包一致。
- 在 Jellyfin 管理后台确认客户端名称为 `Jiaying`，设备分别显示为 `iPhone` 和 `Apple TV`，版本号与安装包一致。
- Release 包中不得出现“演示内容”开关或演示场景。
- iOS 与 tvOS UI 套件必须覆盖未登录 Jellyfin 的冷启动首帧点击，并确认直接进入设置页。
- iOS 和 tvOS 安装包根目录必须包含 `PrivacyInfo.xcprivacy`：明确不跟踪、不向开发者收集数据，并为 App 自有 UserDefaults 声明 `CA92.1`。
- 确认 iOS App Icon 为 1024×1024 且无透明通道；tvOS 大/小图标分层和两种 Top Shelf 图片尺寸与 Asset Catalog 声明一致。
- 用 `-showBuildSettings` 确认 Release 为 `-O`、`ENABLE_TESTABILITY=NO`、Bundle ID 与签名团队正确。

## 2. 自动验证

```bash
cd FamilyMediaClient
swift test

# 先用 -showdestinations 选择本机已安装的模拟器
xcodebuild \
  -project FamilyMediaClient.xcodeproj \
  -scheme FamilyMediaiOS \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  test

xcodebuild \
  -project FamilyMediaClient.xcodeproj \
  -scheme FamilyMediaTV \
  -destination 'platform=tvOS Simulator,name=Apple TV 4K (3rd generation)' \
  test

xcodebuild \
  -project FamilyMediaClient.xcodeproj \
  -scheme FamilyMediaiOS \
  -destination 'generic/platform=iOS' \
  -configuration Release \
  CODE_SIGNING_ALLOWED=NO \
  build

xcodebuild \
  -project FamilyMediaClient.xcodeproj \
  -scheme FamilyMediaTV \
  -destination 'generic/platform=tvOS' \
  -configuration Release \
  CODE_SIGNING_ALLOWED=NO \
  build
```

- 五项命令必须全部成功且没有新增编译警告。UI 冒烟测试必须覆盖首次引导、来源入口、设置入口和媒体库导航。
- 执行 `git diff --check`。
- 搜索生产代码，确认没有 `print`、`debugPrint`、Token、密码或完整认证播放 URL 的日志输出。

## 3. 安装与配置持久化

首次安装、设备配对与覆盖升级步骤见 [apple_installation.md](apple_installation.md)。

- 全新安装后，iPhone 和 Apple TV 都只展示一次欢迎引导；完成后重新启动不得重复出现。
- iPhone 欢迎页的“开始连接”整块按钮必须可以点击，关闭引导动画完成后可靠进入设置；“先看看首页”进入媒体首页。
- iPhone 的“开始连接”应直接进入设置；两端设置页的“再次查看使用引导”可以重新打开说明。
- 分别覆盖安装到真实 iPhone 和 Apple TV，不先删除旧版本。
- 确认家庭媒体地址、Jellyfin 地址、播放数量和照片停留时间仍被保留。
- 用旧构建写入越界的播放数量或照片停留时间后覆盖安装新版：启动不得崩溃，设置页必须显示修复后的有效值，且播放器可正常启动。
- 确认 Jellyfin 登录仍有效；退出 Jellyfin 不影响家庭媒体。
- 完全结束 App 后重新打开，重复确认配置与登录状态。
- 修改 Jellyfin 地址后，旧服务器 Token 必须被清除并要求重新登录。
- 模拟保留 Keychain 但清空 UserDefaults 的重装状态：启动后必须清除孤立的 Jellyfin Token，不得将它发送给默认服务器地址；正常覆盖升级则应迁移并保留原登录。
- 保存任一服务的新地址、完成 Jellyfin 登录或退出后直接返回首页，来源卡片必须立即显示新状态，不需要手动点“重新检查”。
- 将测试配置写成无效、FTP、带账号密码或带查询参数的地址时，App 不得启动崩溃或使用该地址；应回退到安全默认值。
- 在“检查连接”或 Jellyfin 登录尚未返回时修改并保存地址，旧请求不得覆盖新地址状态，旧 Token 不得重新写入。

## 4. 首页与媒体浏览

- 首页正确显示家庭媒体和 Jellyfin 的“正在检查、可用、需要登录、暂时无法连接”状态。
- Jellyfin 未登录时，iPhone 进入设置 Tab，Apple TV 进入设置页，而不是打开必然失败的列表。
- 完全结束 App 后在未登录 Jellyfin 的状态下冷启动，并在首页出现后立即点击 Jellyfin：首帧就必须进入设置，不得因连接检查尚未开始而短暂进入媒体库。
- 临时关闭 NAS 后，入口仍允许进入并显示可重试错误；NAS 恢复后能够刷新成功。
- 进入至少包含 200 个项目的目录，持续滚动并触发两页以上分页。
- 使用网络调节器增加 NAS 延迟后滚动到每页末尾；下一页应在最后几张卡片出现时提前加载，不应等到完全触底才开始，也不得重复请求同一个 cursor。
- 刷新过程中旧内容保持可见，旧分页响应不得覆盖刷新结果；刷新完成后已经加载的分页深度不得退回第一页。
- 从播放器退出后，iPhone 回到最后观看项目附近，Apple TV 焦点回到最后观看项目。
- iPhone 使用最大辅助功能字号打开首页、媒体库和诊断页；媒体卡片应减少列数，长标题允许换行且按钮仍可到达。恢复默认字号后网格列数与布局正常。
- 分别打开空媒体库与空文件夹，两端应显示对应语义和图标，不得把空文件夹误称为媒体库，也不得显示永久加载状态。
- 在 iOS 媒体库中进入文件夹再返回，父级列表应停留在刚才打开的文件夹附近；在 Apple TV 上执行同样操作时，遥控器焦点应回到原文件夹卡片。
- iPhone 首层家庭媒体或 Jellyfin 页面返回按钮显示“媒体”，不得出现英文 “Back”；更深层返回文案使用实际上级名称。
- 停留在家庭媒体深层目录时登录或退出 Jellyfin，当前家庭媒体导航不得被清空；Jellyfin 登录失效时，iPhone 与 Apple TV 应离开受影响的旧目录，而家庭媒体不受影响。
- iPhone 上混合横图、竖图、长短标题与缺失封面的同一网格必须保持统一卡片尺寸；相邻卡片及点击区域不得重叠，最后一行可以完整滚动到 Tab 栏上方。
- 家庭媒体曾连接成功后再关闭 NAS，设置页不得继续显示旧的“可用”状态；修改地址后旧健康结果必须清空。
- 关闭家映的本地网络权限后，连接失败文案应提醒检查权限；iPhone 诊断页可以打开家映的系统设置页。

## 5. 图片与照片

- 快速滚动包含大量封面的列表，确认没有明显闪退、持续增长的内存或错位封面。
- 用 Instruments 检查长列表封面解码尺寸不超过 800 像素；连续滚动 500 张封面后，图片缓存应受限且离屏网络请求能够被取消。
- 连续查看至少 30 张手机原始照片，包含横图、竖图、HEIC 和大尺寸 JPEG。
- 打开一张超高分辨率或大文件照片，确认加载期间没有明显内存峰值导致的卡顿或退出；离开后内存能够回落。
- 快速来回滚动含重复封面的长列表，确认同一封面不会闪烁或反复下载，离开列表后网络与解码任务能够停止。
- 在封面尚未加载完成时快速返回并立刻重新进入同一目录，第二次请求必须正常显示图片，不得被上一次取消结果误判为失败。
- 快速滚动后立刻反向滚动，观察复用中的卡片只能显示自己的封面或占位图，不得短暂闪现相邻媒体的旧封面或失败图标。
- 在慢网下连续进入、退出同一目录并快速反向滚动，较早完成的封面请求不得覆盖复用后卡片正在展示的新媒体封面。
- iPhone 验证双指缩放、拖动、双击放大与还原；放大期间照片不得自动切换。
- iPhone 放大照片后旋转到横屏再转回竖屏：照片应按新尺寸重新适配，检查状态必须结束，之后自动切换仍能继续。
- iPhone 照片成功显示后，确认顶部和底部控件约 4 秒后自动收起，单击照片可以恢复；加载中或加载失败时关闭入口必须保持可见。
- 开启 VoiceOver 后进入照片与视频查看器，控件不得自动收起；单击与双击缩放仍应分别生效。
- Apple TV 验证上一张、下一张、自动播放和“减少动态效果”。
- Apple TV 从顶部切换到“月份”或“年份”后，首批内容加载完成时焦点应落到第一张卡片；遥控器可继续上下移动，播放返回后恢复到刚才的时间线项目。
- 将连续自动播放限制临时调小，确认达到限制且后面仍有内容时出现“继续播放 / 返回列表”；继续后从下一项开始新的计数，返回后 iPhone、iPad 与 Apple TV 均定位到刚播放的项目。
- 照片或视频自动切换到下一项时，顶部与底部控制区域不得重新弹出；手动滑动或点击上一项、下一项时仍应显示控制。
- 为一个家庭媒体视频重新生成封面，返回列表后该项目必须显示新封面，其他可见项目不得被强制重新下载。
- 在封面仍在重新生成时立即关闭播放器，请求应被取消，不得在已退出的页面继续刷新或显示失败提示。
- 断开网络后打开未缓存照片，确认显示失败提示；恢复网络后点“重新加载”成功。
- 在慢网下打开大照片，确认自动播放从照片实际显示后才开始计时；加载失败时不得自动跳到下一张，重试成功后恢复计时。
- 将自动锁定或屏保时间调短后再次触发照片加载失败，确认失败页不再保持设备常亮；点“重新加载”进入加载状态后应重新保持常亮。
- 触发或模拟系统内存压力后，App 应继续运行，图片可按需重新加载。

## 6. 视频播放

- 家庭媒体 H.264 MP4 能直接播放。
- Jellyfin H.264 MP4 在管理后台显示 Direct Play。
- AVI/XVID 等不兼容文件能播放画面和声音，管理后台显示 H.264/AAC Transcode。
- iPhone 验证拖动进度、静音切换、暂停、继续和当前时间显示；静音不得导致播放暂停。
- iPhone 横屏播放时，时间轴、静音、播放、上一条、下一条和关闭入口都应位于安全区内；底部控制栏采用紧凑间距且不得遮住主要画面。
- iPhone 播放中控制栏约 4 秒后自动收起，单击画面恢复；暂停、准备、缓冲或失败状态不得自动收起。
- Apple TV 验证时间轴、缓冲进度、控制栏自动隐藏和遥控器焦点；实体遥控器 Play/Pause 键必须直接生效。
- Apple TV 暂停视频后控制栏必须保持可见；继续播放后才重新自动收起。快速切换照片和视频时，上一项的隐藏计时器不得让新项目的控件突然消失。
- Apple TV 开启 VoiceOver 后，查看器控制栏不得自动收起，焦点朗读和遥控器操作应保持可用。
- 两端播放视频时只应看到家映的一套控制栏，不得在其下方叠加系统 `VideoPlayer` 控件。
- 在播放开始 15 秒内退出，Jellyfin 停止位置不得固定为 0。
- 快速连续切换三个视频，旧视频不得重新抢占播放器，旧转码任务最终停止。
- 在一个视频即将报错或播放结束的瞬间快速切换下一条：排队中的旧 AVPlayer 通知不得让新视频进入失败页、再次跳到下一条或覆盖新进度。
- 连续进入和退出播放器至少 30 次，确认 AVPlayer、通知/时间观察器和系统音频会话不会累积；退出后其他 App 的音频应能恢复。
- 在 Jellyfin 转码视频仍显示“正在准备播放”或“正在缓冲”时立刻退出，NAS 上对应转码任务也必须停止。
- 模拟慢网并连续拖动或暂停后立即退出，停止上报不得被旧进度请求长时间阻塞。
- 在 Jellyfin 管理后台观察上述慢网退出场景：进行中的进度请求应被取消，`Stopped` 应优先到达，转码进程不应继续等待客户端请求超时。
- 播放中进入后台再返回：视频保持暂停，不自动跳到下一项，手动继续后从离开位置附近恢复；停留在后台时启动音乐或其他视频 App，其音频应立即正常输出。
- 上述后台过程在 Jellyfin 管理后台必须先结束旧播放会话和转码任务；返回家映时生成新的 PlaybackInfo/会话，反复锁屏不得累积 FFmpeg 进程。
- iPhone 开启静音拨片后播放视频，媒体声音仍按系统媒体音量输出；退出播放器后其他 App 的音频可以正常恢复。
- iPhone 播放中触发来电、闹钟或拔出正在使用的耳机，视频必须暂停且不得在中断结束后自行继续；手动继续后声音与进度正常。
- Apple TV 播放时切换或临时断开当前音频输出，视频应安全暂停，重新连接后由用户手动继续。
- 将系统自动锁定/屏保时间调短：照片浏览、视频准备、缓冲和播放期间不得自动锁屏或进入屏保；暂停、失败、退到后台或退出播放器后必须恢复系统默认休眠。
- 连续进入、退出查看器并快速切换照片/视频后，最后一次退出必须恢复自动锁定或 Apple TV 屏保；即使 SwiftUI 因旋转或来源切换重建查看器，也不得遗留常亮状态或旧的自动切换计时器。
- NAS 断网、Token 失效、转码失败时显示可理解的错误和重试入口，不出现无提示黑屏。
- 播放中短暂断开 NAS：界面不得显示英文 AVPlayer 错误或系统错误码，应提供“重新尝试”和“返回媒体库”；恢复网络后重新尝试可以重新请求播放方案。
- 视频播放超过 30 秒后中断网络再恢复，点击“重新尝试”应先显示“正在恢复播放”，重新请求 PlaybackInfo，并从中断位置前约 2 秒继续，而不是从头播放。
- 在恢复播放尚未定位完成时立刻切换视频或退出，旧定位回调不得启动旧视频；新视频必须从自己的开头播放，NAS 上旧 Jellyfin 会话最终收到停止上报。
- 播放中让 NAS 或代理保持连接但停止返回 HLS 分片，连续缓冲约 30 秒后必须结束无限等待，显示可重试提示并停止旧 Jellyfin 会话；在 30 秒内恢复、暂停、切换媒体或退出时不得误报超时。
- 让 Jellyfin Token 失效后进入或重试播放：播放器应明确提示重新登录且不显示无效的重试按钮；退出后 Jellyfin 来源和设置页立即显示需要登录，家庭媒体仍可使用。
- 选择服务器无法直放或转码的文件：只提示当前视频无法播放并允许返回，不应诱导用户反复重试。

## 7. 安全与长期运行

- 密码只存在于登录表单内存，登录完成或失败后均被清空。
- 在登录前输入密码后返回上一页，或让 App 进入后台，再次打开 Jellyfin 设置时密码必须为空；用户名和地址仍保留。
- Token 只存 Keychain；地址存 UserDefaults。
- 使用新账号重新登录后，重启 App 应只恢复新会话；Keychain 更新失败时不得先删除上一份有效会话。
- 在旧请求返回 401 的同时完成一次新登录，新 Keychain 会话必须保留；条件失效检查与删除必须是同一个原子存储操作。
- Jellyfin 封面和照片 URL 不得包含 `api_key`；图片请求通过认证头发送，并使用无磁盘缓存的临时会话。退出或切换会话后不得复用上一会话的内存图片缓存。
- 在已经打开的 Jellyfin 长列表中让 Token 失效后继续滚动加载新封面或打开未缓存照片：客户端必须清除失效登录并刷新 Jellyfin 状态；若旧图片 401 晚于一次成功的新登录返回，不得清除新会话。
- Jellyfin 播放 URL 可为保证 AVPlayer/HLS 分片兼容而保留短期查询认证，但不得写入日志、诊断报告或持久缓存。
- Jellyfin 返回的绝对转码 URL 必须与配置的协议、主机和端口同源后才能追加 Token。
- 让 App 在前台持续浏览和播放至少 2 小时，确认无崩溃、明显内存增长、重复声音或遗留转码任务。
- iPhone 锁屏、解锁、横竖屏切换以及 Apple TV 进入屏保再返回后，导航和播放状态仍可控。
- 在媒体页首次加载或手动刷新期间立即锁屏/切后台，再迅速返回；已取消的请求应立即重试，不得在骨架屏或“等待检查”状态停留 30～60 秒。
- 在长目录刚触发下一页预加载时锁屏、进入子文件夹或打开播放器：NAS 上的该分页请求应被取消，已有卡片不消失；返回可见页面后用原 cursor 继续且不重复内容。
- 离开 App 超过 60 秒后再返回，当前媒体列表应在保留旧内容的同时自动更新；短暂打开控制中心不应连续请求 NAS。
- NAS 离线时回到前台应显示不可用或更新失败，NAS 恢复后再次回到前台或手动重试应恢复正常。
- App 保持前台时关闭再恢复 Wi-Fi，或在蜂窝网络与家庭 Wi-Fi 间切换：来源状态应在网络稳定后自动重新检查一次，不需要重启；一次切换过程不得连续触发多次 NAS 健康检查。
- App 在后台期间切换网络，回到前台后应立即消费一次待处理的网络恢复检查，即使距离上次检查不足 30 秒；后续短暂前后台切换仍应受正常节流限制。
- 进入至少三层文件夹后切到后台超过 60 秒再返回：只允许当前可见文件夹刷新，NAS 日志不得同时出现每一层父目录的请求；逐层返回时过期父目录才各自刷新并保留原位置。
- 在当前文件夹加载失败后恢复 Wi-Fi 或 NAS：可见文件夹应自动重试，不需要先返回来源首页；若网络在播放器覆盖期间恢复，应在退出播放器后再刷新列表，不得在视频背后抢占带宽。
- 启动连接检查或媒体扫描后立即退出该设置页，客户端应停止后续等待或扫描轮询，重新进入后仍可正常发起操作。
- 扫描状态标题应显示“尚未更新、正在更新、更新完成、更新失败”等用户文案，不得直接出现 `idle/running/completed/failed` 服务端枚举值。
- 模拟扫描权限失败、未知 5xx、JSON 格式不兼容和 Jellyfin 服务器异常：界面不得显示 HTTP 状态码、服务端错误码、Swift 解码路径、NAS 文件路径、SQLite/FFmpeg 或英文 `permission denied`；应显示对应的中文检查建议。
- 内容更新与连接详情不得显示扫描任务 ID、`ready`、`ffmpeg` 等实现术语；没有返回的统计项应直接省略，而不是堆叠大量 `-`。
- Jellyfin Token 失效后回到前台，应自动清除失效会话并显示“需要登录”，家庭媒体入口仍保持可用。
- 让 App 停留在设置页后使 Jellyfin Token 失效，再切到后台并返回；设置页的“已登录”状态也必须同步消失，不得要求退出页面或重启 App。
- 在首页连续触发两次“重新检查”后立即切到后台；NAS 日志中不得在页面任务取消后又凭空启动第三次来源检查，回到前台后仍可正常手动刷新。
- 在 30 秒内反复进入媒体库并返回来源首页，NAS 日志不得每次都新增家庭媒体和 Jellyfin 健康检查；超过 30 秒后再次返回应正常更新。
- 启动一次耗时较长的家庭媒体更新后离开设置或切到后台：NAS 扫描应继续、客户端轮询应停止；重新进入设置或返回前台后进度应自动续接，完成后媒体列表只刷新一次并能看到新增内容。
- 家庭媒体仍在更新时从系统多任务界面彻底结束家映，再重新打开并进入家庭媒体设置：客户端必须从 NAS 自动发现正在运行的任务并继续显示进度；若离开期间已完成，应只触发一次媒体刷新。
- iPhone“帮助与诊断”能够检查两个来源并复制报告；Apple TV 诊断页在常用观看距离可读。
- 诊断报告可以包含服务器地址，但不得包含 URL 用户信息、密码、查询参数、Token、Jellyfin 用户名、媒体名称或设备 ID。
